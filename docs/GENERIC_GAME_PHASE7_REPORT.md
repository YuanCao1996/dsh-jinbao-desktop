# 第七批：解除五子棋绑定，验证通用观察协议

## 本批完成

- 默认实验模式改为 `generic`，不再默认启动五子棋像素解析器。
- 五子棋保留为用户可选的结构识别能力，不修改其算法和原有回归预期。
- 控制器、DSH 会话和窗口观察共用同一条链路。
- 新增通用画面事实协议：画面类型、已识别文本、对象、来源和归一化区域。
- 棋盘、手牌、菜单、结算和其他画面使用同一协议，不逐个新增游戏解析器。
- `unread`、`partial`、`read` 区分“已截到画面”和“已读懂画面”；未知内容不生成虚假的棋盘、牌面或游戏身份。
- 原窗口尺寸、裁剪坐标和输出尺寸可随观察进入状态和模型上下文；不接受越界、尺寸错配或其他窗口的映射。
- 对象区域的坐标系明确为裁剪后图像的归一化坐标，不与整个桌面的坐标混用。
- 初次通用提问不要求先手动截一帧，DSH 可以在已授权窗口会话中调用观察工具。
- 在首次补充观察时不误取消正在等待工具结果的请求；已有事实发生变化时继续保留旧回复抑制。
- 页面默认显示窗口观察，不再无条件绘制五子棋棋盘。

5 类画面的测试是共同状态协议的结构化回放，不是云端视觉准确率测试。
额外覆盖未知画面、非法区域、旧窗口观察、首次提问、源窗口尺寸及裁剪映射。

无 JS 异常、无横向溢出，默认通用模式，观察占位内容非空。
浏览器测试的窗口列表为受控测试数据，没有抓取其他应用画面。

本批没有请求云端、上传截图或扩展费用额度。
海克斯大乱斗目录、正式启动器、服务端和正式包发布配置均未修改。

## 仍未完成

当前默认通用模式只能安全地取得授权画面，通用视觉阅读器和 OCR 尚未连接。
因此状态明确为 `visual_status=unread`，不能宣称已识别游戏种类、牌面、菜单或战绩。
这批解决了“核心绑定具体游戏”的问题，不代表通用游戏理解已经完成。

下一批应先验证服务器桌面接口及 OpenCode Go 上游的图片输入能力，再接入同一套通用读图工具：

1. 只接受已授权窗口的新鲜裁剪帧，保留坐标与尺寸；默认小图，必要时提高区域清晰度。
2. DSH 决定什么时候需要读图，不能因为本地采样频率提高而同步放大模型调用次数。
3. 模型输出进入通用事实协议，未知项保留未知；不让图中文字变成工具指令。
4. 图片请求与窗口、会话、帧身份绑定，超时或切换窗口后丢弃旧结果。
5. 使用不同画面和问题验证同一套实现，不为每个游戏复制一套调度、记忆或截图代码。

服务器目前桌面模型接口只接受文本/工具消息，不能仅在客户端附图就认为上游可用。
尚未验证 Go 上游的实际图像兼容性，不自动回退 Qwen 或本机直连厂商接口。
上一批开发会话已到期，模型按设计关闭；没有自动续期或重新签发账号。
