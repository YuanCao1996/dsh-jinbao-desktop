# 桌面通用游戏助手开发计划

## 范围与现有产品保护

先在桌面验证，暂不修改 Android APP。产品工程为 `publish/jinbao-desktop-public`，
`publish/jinbao-testkit` 仅提供测试素材与可复用能力参考，不整套搬入产品。

- LoL 的采集器、适配器、人设、事件触发和模型配置保持不变。
- 新模块默认关闭，不注册到已有启动器、DSH 插件、发布打包白名单。
- 不监听 LoL 日志，不读取 LCU，不创建 `coach-lol` 会话，不写现有悬浮窗状态文件。
- 不启动额外 OCR 模型或自动云端请求。显式启用后只访问用户选定窗口。
- 后续接入必须独立开关、独立采集进程、资源限额与可独立停止；不以未知游戏回退到 LoL/王者。
- 两模式不能同时抢占实时采集；通用模式启用前需明确检查专用模式是否活跃。

## 模块与依赖

| 目录 | 职责 |
|---|---|
| `tools/game-observation` | 授权窗口、归一化 ROI、清晰度、帧时效、观察频率与调用预算 |
| `tools/generic-game-assistant` | 通用控制器、结构化上下文、各棋牌适配器与回放 |
| 现有 `dsh-coach-server` | 当前 LoL/王者服务，本批不改；后续通过受限桥接复用宿主能力 |
| 现有 `dsh-onboarding` | 当前设置与认证，后续新增独立设置，保留原配置 |
| 现有 `desktop-release` | 当前安装与 WPF 悬浮窗，后续按选定模式增加展示，不复制整套 |

依赖方向为游戏适配器 → 公共观察协议 → 平台采集实现。
公共观察器不含 LoL、王者、五子棋的规则或提示词。
DSH 只能提出观察请求，不能执行任意路径读写、系统命令、鼠标或键盘输入。

## 第一批：已实现的独立基础

- 协议版本 1，明确授权目标窗口；ROI 为窗口内 0～1 的坐标，按实际像素向外取整。
- 概览/标准/局部细节最长边上限分别为 960/1440/2048，不放大小图，不改变纵横比。
- 缺少目标、窗口不在前台/不可见、未排除助手画面时不允许使用帧。
- 观察默认至少间隔 1 秒；更慢的请求也须被尊重。模型调用默认冷却 10 秒，每局最多 30 次。
- 自动分析按局面哈希去重；用户追问也受冷却和预算约束。失败消耗预算，不无限重试。
- 本阶段只在明确提问时调用注入的分析器，不自动请求模型。生产 DSH 连接尚未接入。
- 五子棋只验证输入结构、格子枚举和已知/未知字段，**未进行合法性、胜负、禁手或最佳落子计算**。
- 独立会话 ID、局面修订号、取消信号、15 秒超时；迟到回复与过期观察不得显示。
- 新的无效观察会清空可用状态，不把上一帧继续当作当前棋盘。
- 同局面刷新可更新观测时间而不触发重复分析。快照防外部修改。
- 临时解释历史有界，仅用于基础测试；正式对话记忆接入 DSH 原生会话，不另造完整记忆系统。
- 独立结构化诊断回调，日志故障不影响观察。落盘与轮转在平台接入批次实现。

第一批中的 `assistant_excluded` 仅是采集器必需证明字段，当时未实现 Windows 的真实窗口排除。
第一批回放为合成结构化观察与模拟分析器，不是截图 OCR 回放，也不是云端效果测试。

## 第二批：Windows 真实画面观察

1. 用户选择明确的进程/窗口句柄；不要只靠窗口标题模糊匹配，也不要失败时抓整个桌面。
2. 新建独立、惰性加载的桌面采集实现。参考测试包截图/OCR代码，不启动它的 LoL 调度循环。
3. 核对 DPI、多显示器、负坐标、窗口移动缩放、前台身份及遮挡。
4. 排除金宝窗口与工具进度；无法证明排除时返回不可用，避免识别自身建议。
5. 返回真实图片哈希、区域、时间戳、尺寸及来源，并按受限目录保存测试截图。
6. 先在受控棋盘页面实际截屏、定位棋盘、识别棋子，再做多皮肤截图集。

第二批已实现独立Windows客户区采集和有限棋盘像素识别，并在真实受控测试窗口验证。
实际棋牌皮肤、多显示器及不同DPI仍待验证；本批没有文字OCR和云端视觉补偿。
详见 `GENERIC_GAME_PHASE2_REPORT.md`，不将受控窗口结果当作真实游戏验收。

## 第三批：独立 DSH 工具与用户入口

- 不复用强制 LoL 文案的请求拼接器，只复用宿主、模型路由、凭据和原生会话 API。
- 新工具限定当前授权目标：读取局面、请求局部观察、提出观察策略、分析已验证局面。
- 模型不得通过工具参数修改用户/目标身份、输出路径或取消资源限制。
- 观察策略有短期有效期，本地轻量画面变化触发复查；不为判断是否截图先调用模型。
- 桌面设置添加实验模式开关，默认关闭；悬浮窗显示真实观察/工具进度，不显示思考过程。
- 保持现有 LoL 启动、设置和页面行为。实验模块关闭后零额外采集、零模型流量。

第三批已完成独立DSH适配代码、受限工具与本地调度，并通过真实SDK/模拟模型测试。
尚未安装到运行中的DSH，也未完成云端模型联调或正式设置入口。
SDK混载会拒绝启动，不能靠全局注册降级；详见 `GENERIC_GAME_PHASE3_REPORT.md`。

## 第四批：规则与棋力引擎

首发五子棋，先确认自由规则/禁手规则，再选择成熟引擎并核查许可证。
不让 LLM 自己实现规则或计算最佳棋步。局面先验证，随后调用引擎，DSH仅解释结果。
再按象棋、围棋、斗地主顺序评估。单图不够恢复历史时，明确缺失，不猜历史着法或对手手牌。

## 测试门槛与指标

- 原有 `npm test` 必须持续全部通过；新功能使用 `npm run test:generic`。
- `npm run test:all` 顺序运行两组测试，不改变原测试入口。
- 基础测试覆盖默认关闭、授权、ROI、清晰度、预算、去重、未知、取消、超时、跨局与日志故障。
- 后续真实截图覆盖 1080p/2K、超宽、窗口模式、DPI、多显示器、遮挡、动画及反复切换目标。
- 测试分为结构模拟、真实 OCR 回放、真实 DSH/云端；报告必须标清，不能互相替代。
- 记录截图、识别、排队、视觉、工具、引擎、总耗时；图片尺寸/字节数、模型 token 和每步调用数。
- 对比同截图固定整屏方案与自适应方案的关键要素准确率、P50/P95延迟和成本，不预先承诺节省百分比。
- 验证 LoL 开关前后事件量、采集频率、CPU与内存，默认关闭时不能出现实验模块活动。

## APP 迁移

复用版本化 JSON 契约、测试集、DSH 工具与服务端引擎。
Android 单独实现截屏、窗口/前台边界、资源调度与悬浮窗；Windows/Node/PowerShell代码不直接搬入Java。
本次不发布、不重启 DSH 宿主、不修改 APP 或线上服务。
