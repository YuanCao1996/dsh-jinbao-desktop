## 用户体验与边界

- 保留 DeepSeek Harness Desktop 作为 Agent 宿主，复用会话、上下文、工具和模型执行能力。
- 用户点击“金宝”桌面快捷方式；解压版提供“开始使用.cmd”作为同一入口，不再默认进入数字菜单。
- 启动即显示悬浮窗。初始化期间显示“正在启动”，就绪后显示“等待进入游戏”；未登录时显示登录入口，不能把未就绪显示为正常待机。
- 新安装默认金宝官方服务，首次扫码登录，不要求选择模型方案或填写 Key。升级保留已有 BYOK 设置。
- 有效登录自动恢复；设置允许切换 BYOK、退出登录、查看额度和诊断。
- 不要求用户选择游戏。自动检测已支持的游戏；同时检测到多个来源时按真实活跃对局路由，独立保存对局状态。
- 王者手机端仍负责现有识别，电脑通过已有日志通道接收。未连接、USB 未授权、手机端未运行时显示对应状态。
- 不改变现有累计额度和检索权益政策；登录成功与有调用额度是两个状态。IP 体验账户关联微信时不得重复发放或静默转移额度。
- 不承诺微信登录替代宿主自身认证，也不承诺尚未支持的任意游戏都可自动采集。

## 阶段一：验证前置条件

1. 使用隔离的 Windows 用户或虚拟机、兼容 DSH 版本和全新配置，验证无需 DSH 账号时是否能加载插件、创建持久会话、执行工具、调用自定义模型。
2. 确认 DSH 安装来源、支持的安装参数、启动路径、首次配置和插件加载时机。首次安装与日常启动分开；不得每次修改配置和重启宿主。
3. 确认微信开放平台已有网站应用及微信登录权限、回调域名，并确认网站应用与移动应用身份关联条件。
4. 对照线上实际配对实现检查凭据格式：本地后端代码发放 jd_，电脑入口目前只接受 jc_。修复应验证对应身份解析和访问权限，不仅放宽字符串校验。

交付：记录验证结果、兼容版本和首次安装必须由用户完成的动作。网站权限未开通时，启动器和现有配对修复继续开发；直接微信扫码发布等待权限就绪。

## 阶段二：独立启动管理模块

新增 tools/jinbao-launcher，避免把进程管理塞进教练 Agent 或游戏适配器。

- 统一入口负责单实例、运行目录、安装检测、服务探活和状态通知；重复点击显示已有悬浮窗。
- 优先展示悬浮窗，再异步检查宿主。缺少 DSH 时提供官方安装引导，不悄悄终止。
- 首次配置及升级配置复用现有安装器，保留备份。宿主正在运行且需要重启时提示保存工作，不强制结束用户会话。
- 日常启动直接复用已运行服务；需要启动宿主时等待真实就绪，不仅检查 settings-link 文件。
- 桌面快捷方式和开始菜单指向同一启动入口。首版复用内置 Node 和 PowerShell，不引入新的 Agent 运行时。
- 管理所创建采集进程，断开重连、有限重试、退出清理；不能结束用户原本运行的 DSH 或其他 ADB 使用者。
- 悬浮窗关闭即停止本次金宝后台检测和采集；收起保留运行，可从托盘恢复。宿主生命周期按进程所有权处理。

交付：单入口启动，安装/升级与正常使用分流；旧数字菜单保留为高级维护入口。

## 阶段三：默认云端与微信登录

服务端新增隔离的桌面网页登录模块，复用现有身份与权益接口，不重写 APP 登录。

1. 电脑发起短时登录请求，保留仅本机可知的轮询凭据；打开 HTTPS 官方授权页。
2. 用户用微信扫码确认；服务器校验一次性 OAuth state，交换 code 并解析身份。AppSecret 只在服务器。
3. 将验证过的 UnionID 关联至既有金宝账户，或创建新账户；UnionID 缺失时使用明确绑定流程，不按昵称自动合并。保留既有 OpenID 所有权和用户资料。
4. 电脑使用本机持有的凭据领取独立、可撤销的桌面会话；二维码和回调 URL 不携带长期登录令牌。
5. 本机凭据写入现有安全存储，完成权益检查并自动使用官方模型。无额度时显示真实状态，允许去设置配置 BYOK。
6. 设计访问凭据续期与撤销，避免现有短期会话每次过期都必须扫码；明确续期失败、注销和设备退出行为。
7. 修复现有 APP 配对的凭据兼容和成功后自动配置云端，保留为备用登录路径。

新用户默认云端但不会自动消耗试用名额或创建调用；进入游戏且有登录与权限后才执行模型请求。既有用户升级不覆盖 BYOK。

## 阶段四：自动检测与采集路由

新增独立采集监督模块，复用现有 LoL 与王者采集器。

- LoL：低频检测客户端/LCU 与活跃对局；识别已支持模式，出现有效日志后进入对局状态。进程存在不等于有对局。
- 王者：检测已授权手机及已有 APP 日志中的游戏标识。连接手机不等于正在玩王者；多设备避免盲选，必要时仅选择设备。
- 按来源和对局 ID 分离文件、计时、聊天上下文和事件，防止跨游戏或跨局串流。
- 断连时显示采集中断并重试；对局结束后保留结果，回到等待；新对局重置。
- 新增适配器只实现检测、采集和规范化事件接口；此阶段不承诺未知游戏自动识别。

交付：用户不选游戏即可使用当前已支持模式。

## 阶段五：悬浮窗与设置整合

- 保留已有八个页签、对局计时、拖动、收起、托盘和退出能力。
- 新增状态：启动中、等待登录、等待安装、等待进入游戏、手机未授权、正在对局、采集断开、额度不足、服务故障。
- 未登录也能看到悬浮窗和本机采集状态；不生成虚假的云端建议。
- 设置整合模型切换、API Key、微信账户、设备退出、累计额度、检索权限和诊断。
- 前台只有真正需要用户处理的动作；常规服务检测和采集器启动在后台完成。

## 验收与发布

必要验证：

- 全新 Windows 环境首次安装和扫码；已装 DSH 的首次配置；重复启动；升级保留 BYOK；路径含中文/空格。
- DSH 未登录、已登录两种状态；服务端断网、端口占用、权限不足、启动失败。
- OAuth 过期/取消/重复回调、跨设备领取隔离、桌面会话撤销、账户关联及既有额度不重复发放。
- 自动检测 LoL、手机授权和王者日志；双来源、断连恢复、新局和结束；等待状态不调用模型。
- 八页签和对局计时回归；关闭停止本次后台进程，收起可恢复；不结束无关进程。
- 发布包完整性、凭据不入包、数据库不入包、服务端安装包与 GitHub 校验一致。

先本地完成，再使用测试账户做实机验收，最后发布新版本与官网使用说明。保留上一版本及配置备份供回退。

## 完成标准

在前置宿主条件满足后，首次打开金宝即可见悬浮窗；默认官方服务只需首次扫码；后续一次点击进入待机；支持游戏开始后自动采集并给建议；设置可随时切换 BYOK。若宿主强制认证或微信权限未就绪，必须在发布说明中准确标出，不能宣称已经实现完全一键使用。
