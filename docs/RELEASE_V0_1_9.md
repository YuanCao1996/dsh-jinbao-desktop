# 0.1.9：已有悬浮窗兼容修复

已有开发环境在 DSH 启动时会自动拉起旧 LoL 悬浮窗。0.1.8 下载版又启动独立窗口，两者可能重叠并争用 Ctrl+Alt+J，同时下载版停留在等待安装配置的状态。

0.1.9 在启动窗口前识别同一 Windows 会话中明确运行旧脚本的进程；已有旧窗口时直接沿用，不安装覆盖现有 DSH 配置。宿主稍后才启动旧窗口时，下载版结束自己的窗口和采集器。识别仅针对 tools/lol-companion/overlay.ps1，不匹配启动脚本、任意名称相似程序或其他 Windows 会话。

独立打开和关闭悬浮窗的入口也遵循 DSH_HOME，避免自定义状态目录与默认目录错用。

验证：26 项自动测试通过，包括真实 PowerShell 启动入口在“有旧窗口”和“无旧窗口”两个分支的隔离测试。后者替换了模型管理器及窗口为测试记录器，用于验证分支行为，不等同于重做完整宿主端到端验收。0.1.8 已有完整 DSH 启动与上下文恢复验收记录。本机热修复后确认旧窗口为 1 个、下载版管理器和窗口为 0 个、原 DSH 仍运行。

这是兼容修复，尚未提供旧开发配置到官方云端的自动迁移。微信网站扫码和手机完整对局仍待原定前置条件及实机验收。
