# 开黑队伍模块（本地预览）

任务反馈（本地候选）：网页、手机共享页面和桌面群聊状态区使用同一提示逻辑。排队/处理中优先显示；近期失败说明未得到有效回答，信息变化或过期取消说明旧回答未发布，已结算恢复说明只核对用量、不补发旧回答。待核对任务持续提示普通聊天可用，不自动重试模型；普通失败提示5分钟后消失，新任务完成后不再显示旧失败。只用白名单文案，不展示原始提供者错误、思考过程或工具内容。它是状态提示，不会自行触发新请求。已同步App源码资源，但未安装APK或完成可视验收。

登录失效处理（本地候选）：轮询、发送和其他操作收到401或明确身份校验失败时，清空群消息、记忆、预算与确认显示，暂停主机与信息共享。暂时失效保留房间选择，重新登录后由服务器验证成员资格，无需再次两端配对；共享需主动重新开启。明确退群、移除或房间不可用时清除房间选择，并沿用本机工作缓存撤权清理。暂时网络/服务故障不当作撤权；已经发出的旧轮询不能在失效后恢复界面内容。该处理不等于账号注销生命周期已完成。

2026-10-29候选新增：`usage-outbox.mjs` 独立加密保留最小用量记录。断网或设备撤权后，可用仅限原任务的授权补交已知token数量，只结算原房间/主机两份上限一次，不补发旧回答、不消耗官方模型额度。未知用量仍待核对。设置“维护与诊断”显示待同步、已送达、待核对计数；未确认记录不会随Agent缓存清理。当前仍未发布，真实提供者、多设备与正式持久化验收尚未完成。

最多5名当前成员，各自采集并共享整理后的本局信息。成员可以增减，房间消息保留，每局使用新的原生 DSH 工作会话。群主为全群选择一个既有导师；群聊只显示最终文字回答，不播报语音。

目前未发布或部署群服务。桌面入口需显式开启 `--team-rooms`；Windows 自有模型群主机还需 `--team-byok-host`。服务端也必须在隔离环境显式开启对应功能，客户端开关不会授予服务端权限。普通用户安装的现有版本不会因此自动开启。

## 两种模型执行方式

- 官方云端：电脑、手机都只需金宝登录和群主授权的房间预算，不要求安装本机 DSH。
- 自有模型：一名电脑成员使用已安装 DSH Desktop 的原生依赖和金宝设置中的自有模型。房间协调、历史、资料查询及权限仍经过服务端；不是离线群聊。模型密钥留在电脑，不发给队友或金宝服务。

Windows 主机预览流程：

1. 在金宝设置配置已有“自有模型”方式，填写独立模型地址、模型名和密钥；安装 DSH Desktop 或填写其程序路径。
2. 登录并创建/加入队伍，在队伍设置展开“自有模型群主机 · 预览”。
3. 电脑成员填写设备名称及自己允许使用的累计 token 上限，确认申请。
4. 群主在原登录端批准申请，可用电脑或手机。批准不会自动切换模型方式，也不会发起模型请求。
5. 电脑建立在线连接后，群主明确切换为“已授权电脑的自有模型”，再授权房间预算。房间与电脑两份上限同时生效。
6. 成员正常聊天或 @导师 提问；主机离线不自动切换官方模型，不重复运行已领取的付费任务。
7. 电脑成员可停止并撤回；群主可撤销授权。解散、移除主机、撤销相关身份及转让群主都会使旧授权失效。

已授权设备凭据使用 Windows 当前用户 DPAPI 加密，重启可复用；主机租约仍由服务端确认，不能同时多进程承载。更改模型配置会排空旧运行器，后续重新校验。申请过期或授权撤销后需要重新申请，不会自行开通新额度。

## 实现与边界

- `bridge.mjs` / `mobile-session.mjs`：房间页面和结构化信息协议。
- `local-host.mjs`：原生设备授权、加密存储、启动/停止与恢复。
- `host-client.mjs`：有租约的群任务传输、用量检查点、工具RPC及幂等最终回执。
- `local-runner.mjs`：复用实装 DSH 的循环、会话、JSONL持久化与原生压缩，只挂载本轮授权群工具。
- `agent-policy.mjs`：官方与自有模型共用的群/游戏提示规则；服务端运行目录副本由一致性测试约束。
- `cache-store.mjs`：独立的本机群工作缓存到期、删除意图、重试和本机删除记录，不读取模型密钥或加载DSH。
- `cache-reports.mjs` / `cache-report-format.mjs`：独立加密保存的删除状态授权、有界补传和最小回执格式，不加载Agent或读取登录/模型密钥。

不挂载电脑终端、文件、私人聊天/记忆、原始日志或截图工具。手机只能管理主机元数据，不保存电脑凭据或承载模型。资料工具按服务端权限检索，不把五人的原始流塞进请求。

自有模型接口目前要求兼容 OpenAI Chat Completions 的文本/工具调用，并返回有效 `usage.total_tokens`。缺账单、网络中断或用量不明时保留待核对，不猜测免费或自动重试模型。账务保守检查不是提供者账单审计。

聊天与共同记忆采用“解散后30天可恢复、到期删除”。用户已确认本机可重建工作缓存尽早清理：已知退出群聊、关闭房间或主机授权失效后立即清理；距最近一次成功授权使用超过30天的缓存，在下次启动或载入前清理。电脑关机时无法执行物理清除，恢复运行先清理再允许载入。群消息和长期共同记忆仍由服务端保存，可通过工具重新检索。

缓存维护在桌面启动时独立执行，关闭群入口、切换官方模型或缺少本机DSH/密钥不停止已存在缓存的到期检查。只清理专用 `team-host-sessions`，不触碰个人会话、偏好、模型密钥或原生依赖。无索引的旧预览缓存视为可重建数据，载入前清理。删除前持久化意图，释放原生持久化后再删文件；失败保留待清理状态并阻断旧缓存载入。

设置的“维护与诊断”区分待清理、本机已清理、回执已送达和待补传。固定诊断事件不含正文、玩家名、路径或凭据。本机删除记录只含不透明哈希、代号、时间与原因，保留90天；重新授权不会清掉尚存记录。新版获批主机在领取任务前，先加密保存只用于上报删除状态的授权。断网不影响本机清理；退出、登录过期或群入口关闭后仍可重连补传，每分钟最多5条，失败不密集重试。

服务端“已送达”只表示收到设备报告，不能远程验证所有磁盘副本已删除，也不恢复群阅读、模型执行或结算权限。没有补传授权的旧预览记录保留在本机并显示说明，不为了补传自动重新授权主机。手动导出或完整磁盘备份的处理不在本机缓存删除保证内。

本机清理及删除记录补传已通过本地自动化验收；真实提供者兼容性、Windows/Android控件可视、多设备实战、迟到费用补偿和正式部署仍待验收，当前不作为正式可用功能发布。
